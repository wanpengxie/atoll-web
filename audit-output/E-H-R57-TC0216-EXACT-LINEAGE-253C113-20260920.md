## Scope and user contract

This round covers TC0216 only. TC0212, Feed I/O, virtual-list geometry, and
the product implementation are out of scope.

The user capability is: select the public Claude filter, wheel upward until
the physical history page boundary, and continue to older physical pages until
older Claude rows that were separated by nonmatching rows are visible in the
same filtered presentation. The observable is the real row ID/text and its
ability to remain in the list; a demand diagnostic, a request count, or a
temporary raw-feed cursor is not a substitute.

The preserved old action is a native wheel at the physical top. The preserved
observable is the older matching row becoming visible after durable page
materialization, without a synthetic anchor, a second scroll writer, a
diagnostic-only success, or a stale page overwriting a newer filter/root.

## Minimal safe continuation token

The existing sparse-page idea is retained, but only as a proof tuple captured
by the current `useHistoryConsumer` owner:

```text
P = {
  firstRowID,
  firstRowSeq,
  firstVisibleSeq,
}
```

The result is eligible only when all three observations are exact:

```text
current committed rows[0].id        === captured firstRowID
current committed rows[0].seqLow    === captured firstRowSeq
result.firstVisibleSeq               === captured firstRowSeq
```

`firstVisibleSeq` is a physical-page fact. It does not grant permission by
itself and cannot be replaced with a timer, a matching diagnostic, or a raw
frontier advancement.

The continuation also carries one exact ephemeral lineage tuple. The
implementation may flatten it or place it under `continuation.lineage`, but
every field is required and compared with strict equality:

```text
L = {
  controller,       // current hook/session owner identity
  activationID,     // current Reading activation
  channelID,
  viewKey,
  inputEpoch,       // exact physical input transaction
  intentRevision,   // exact semantic intent revision
  gestureID,        // exact coordinator older-gesture transaction
  rootIdentity,     // exact Vendor physical root generation
  visibilityEpoch,  // exact effective-visible boundary lineage
}
```

`visibilityEpoch` is deliberately not a boolean `surfaceVisible`; visible →
hidden → visible must not make an old timer current again. It must be supplied
by the existing visibility-boundary authority (or the continuation must
fail-stop until that authority can provide it). The red test names this
required boundary explicitly so a product patch cannot silently infer it from
the current boolean or from `inputEpoch >= capturedEpoch`. Base `253c113` does
not expose such a token to `useHistoryConsumer`; that is an explicit owner
handoff to resolve, not permission to mint a second visibility store inside
the consumer.

## Gate and failure rules

The exact `P + L` token is checked at all four points: insertion/commit
invalidation, page settlement, timer execution, and the continuation request
itself. A mismatch at any point must:

1. clear the continuation timer/ref and `topBoundaryRef` (and cancel any
   position-lease waiter owned by the same controller);
2. return the existing fail-closed outcome (`position-anchor-missing` or the
   existing cancellation result), without issuing a successor request;
3. wait for a new user input to capture a new `P + L` and reissue normally.

No `>=` or `<=` comparison is valid for `inputEpoch` or `intentRevision`.
Those values are lifecycle boundaries, not progress counters. A later epoch
can be a different wheel gesture, a direction reversal, a root replacement, or
a visibility re-entry.

## Counterexample matrix

| Interleaving | Sparse proof | Lineage result | Required outcome |
| --- | --- | --- | --- |
| Same older gesture; page has no matching semantic row | `firstRowID`, `firstRowSeq`, and `firstVisibleSeq` all match | all nine fields exact | continue one page |
| Quiet gap, then independent older wheel; same first row remains | may still match | `inputEpoch`, `intentRevision`, and `gestureID` differ | old timer stops; new wheel captures and reissues |
| Newer/reverse wheel before old page settles | may still match | gesture/tail direction and input lineage differ | stop; never let old older request run |
| Claude filter, channel, or view scope changes | row may coincidentally match | `channelID` or `viewKey` differs (or controller/activation changes) | stop; new view owns a new request |
| Same hook/controller, physical list root remounts | row may coincidentally match | `rootIdentity` differs | stop until the new root paints its own evidence |
| Surface hides and re-enters | row and `surfaceVisible === true` may match again | `visibilityEpoch` differs | stop; re-entry must establish fresh authority |
| Hook unmounts | no safe current observation | cleanup retires controller/timer | stop; no late request |
| Result reports another row's or wrong physical sequence | ID may match by accident | `firstVisibleSeq !== firstRowSeq` | stop; do not infer progress |

The `>=` candidate from the preceding round is rejected by the second row of
this matrix: it accepts a newer epoch/revision while the row and frontier stay
unchanged. The old exact-only path is also insufficient for the normal sparse
filtered-page user path because it requires a `historyAnchor.viewportOffset`
at `useHistoryConsumer.js:267-273`, which is absent when no semantic row was
prepended.
