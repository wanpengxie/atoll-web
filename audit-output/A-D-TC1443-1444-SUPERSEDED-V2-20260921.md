# A–D TC-1443/TC-1444 disposition — superseded v2 persistence baseline

Date: 2026-09-21

## Decision

TC-1443 and TC-1444 are **superseded baselines**, not current product regressions and
not migration tests to be submitted. The product decision from the owner is explicit:
the retired frontend persistence format is not compatibility-preserved; a version
incompatibility takes the understandable refresh/restart fallback. Therefore a test
that requires a v2 record to be migrated, or a v2 count-only/key-only record to be
interpreted, contradicts the current product contract.

The red candidate `cac56cb` is intentionally not submitted or cherry-picked. No
`it.fails`, skip, compatibility reader, or replacement red test is introduced here.

## User capability and invariant

- User capability: a page with an incompatible protocol/storage generation stops
  safely and tells the user to refresh; a current page persists only the supported
  view-session contract.
- Invariant: one current v3 persistence owner; an old document must not read or write
  data using an obsolete schema, and recovery must not silently invent state.
- Current owner: `src/model/view-session.js` owns durable view-session parsing/writing;
  `src/ui/VersionIncompatible.jsx` owns the user-visible refresh fallback and
  `src/app/WorkspaceApp.jsx` presents it when the wire reports incompatibility.

## Evidence at base `993b4cf4909db54ee1008e36cf31e5530cd300ab`

- `src/model/view-session.js:109-131` fixes the schema at `3`, reads only
  `atoll.view-session.v3.<principal>`, and returns empty current state when the
  schema does not match. This is a destructive boundary by design, not a missing
  v2 migration hook.
- `src/model/view-session.js:74-86` makes persisted reading start in following mode
  without restoring the old browsing bookmark, so stale middle-position state is not
  silently resurrected after a storage boundary.
- `src/ui/VersionIncompatible.jsx:10-14` explains that the page is expired, says the
  session stopped to avoid incompatible reads/writes, and exposes one explicit
  `刷新页面` action.
- `src/app/WorkspaceApp.jsx:1926-1930` routes the wire incompatibility to that
  fallback and invokes `globalThis.location.reload()` only from the explicit user
  action.

## Original candidate mapping

The retired cases used `atoll.view-session.v2.me` fixtures:

- TC-1443 expected v2 viewport unseen records and derived surplus to migrate.
- TC-1444 expected v2 count-only/key-only viewport unseen records to be interpreted
  at the storage boundary.

Those actions are no longer a supported user capability. Keeping either as a red
current test would demand a compatibility owner the product explicitly removed.
They remain traceable in the central ledger as superseded, with no PASS/FAIL count.

## Scope and verification

This is an audit disposition only. No source, vendor, package, lockfile, private API,
store, compatibility layer, skip, or test assertion was changed. The next unique
baseline handled in this worktree is TC-1445.
