## 4. 系统交错审核规则

所有轨迹叠加：权限/账号切换、后端事实终结、迟到/重复/部分页、存储拒绝、IDB升级阻塞、BFCache、隐藏0尺寸、字体/媒体/异步解析、React重复effect、多tab写入、客户端时钟跳变。

优先级：身份/权限合法性 → 事实归属与版本 → 当前阅读授权 → 组件几何执行。主线程和网络预算不能永久饿死任何有效前台义务。超时用单调经过时间，顺序与终态不由本地墙钟判断。

每轨迹同时检查安全性与推进性：没有错导航不等于消息最终出现；不复活旧任务不等于真实活跃任务不遗漏；不重复气泡不等于发送完成。最终性在网络/权限/资源可用前提下成立；永久不可用需要明确失败与可恢复状态。

## 5. 本轮裁决

原42场景和F01–F28没有删除或降低，新增12条审查轨迹及F29。模型合同缺口已写回R3；没有将组件/接口未核验能力标为运行通过，也没有以这些缺口授予后端修改权。
对应功能的实施完成必须附代码、独立oracle、真实行为证据；本表不是一批测试已执行的计数。
