# atoll-web 用户交互总规格

状态：产品基线
日期：2026-08-17
关联文档：[产品交互总任务](PRODUCT-INTERACTION-MASTER-PLAN.md)

## 0. 规格定位

本文是 atoll-web 唯一的总用户交互规格，按完整用户旅程定义产品，而不是按后端 verb 拆分页面和按钮。

文档层级固定为：

1. **产品交互总任务**：说明为什么做、能力范围、Mock/真实后端边界和实施路线；
2. **用户交互总规格**：说明用户看见什么、如何进入、怎样完成任务、系统如何反馈；
3. **技术附录**：只承载跨多个旅程复用、实现复杂且容易产生歧义的状态模型。

当前技术附录只有：

- [频道访问状态](interaction-specs/channel-access-state.md)；
- [普通消息与结构化终态](interaction-specs/message-and-structured-terminal.md)。

`cancel`、`steer`、`channel.create` 等协议动作不再各自建立长规格，它们分别归入“控制长任务”和“管理频道”旅程。

## 1. 产品定位与用户心智

atoll-web 是一个以频道账本为核心的人机协作客户端。用户在其中：

- 查看频道内已经发生的事实；
- 与人、Agent 和工具协作；
- 发起、观察、调整或取消长任务；
- 处理审批和结构化结果；
- 管理频道、成员、能力和资源；
- 在具备权限时管理空间级模板、端点和设备。

用户应理解的概念只有：

- **空间**：频道、成员和资源所属的协作环境；
- **频道**：围绕一个主题持续协作的工作区；
- **消息账本**：频道中可追溯的消息、动作和结果；
- **成员 / Actor**：参与频道的人、Agent 或工具；
- **任务**：一次可能包含多个回合、工具调用和结果的工作。

WS、OBS、registrar、coreactor、系统 seat 等实现概念不直接暴露给普通用户。

## 2. 信息架构

### 2.1 登录前

只提供注册、登录和会话恢复。lobby 是认证入口，不作为登录后的可见频道。

### 2.2 登录后

桌面端采用三栏工作台：

- **左栏**：我的频道、空间中可发现的频道、未读状态、创建入口；
- **中栏**：频道标题、消息账本、任务过程、终态、审批和输入区；
- **右栏**：成员、Actor 能力、文件与频道设置；
- **全局层**：连接状态、后台操作、通知和账户菜单。

窄屏按“频道列表 → 频道工作区 → 详情面板”逐层进入，并保留明确返回路径。

### 2.3 左栏

“我的频道”只显示当前 principal 具有有效成员关系的频道。“空间”显示可发现但尚未加入的频道，两者不可混在同一个无语义列表里。

频道项至少显示名称、未读、运行/不可用状态；需要用户处理审批或任务终态时显示更强提示。隐藏 `system`、`registrar`、`svcactor` 等标准系统 Actor。

### 2.4 中栏

消息区占满中间工作区，不再嵌套一个与页面重复的外框。输入区固定在可见底部；无发送权限时在原位置解释原因，而不是直接消失。

切换频道必须切换标题、账本、输入上下文、未读游标和右侧详情。后台任务仍绑定原频道，不得因当前频道改变而串写状态。

### 2.5 右栏

默认展示可理解的成员名、类型、状态和能力。治理入口只有在权限成立时出现；系统 Actor 默认完全隐藏，诊断模式下才允许查看。

## 3. 全局交互原则

### 3.1 写操作的三阶段反馈

所有写操作统一呈现：

1. **正在提交**：浏览器正在发送；
2. **已接受，等待账本确认**：后端 receipt 已接受，但事实尚未进入 feed/OBS；
3. **已确认**：账本或投影已经出现对应事实。

超时代表“结果未知”，不能直接等同失败。用户可以重试查询或安全重放，但界面不得凭空宣告成功。

### 3.2 对象绑定

消息、任务、审批和后台操作都绑定自身的频道与对象标识。切换当前频道只改变视图，不改变这些操作的归属。

### 3.3 权限可解释

无权限状态应在用户行动前表达：隐藏仅对管理员有意义的入口；对用户可理解但当前不可执行的动作，禁用并说明缺少的权限、成员关系或频道状态。

### 3.4 结构化结果是一等内容

文本、工具活动、审批、文件、取消、错误、重定向和治理结果都以对应组件显示，不把 JSON 原样塞进普通气泡。

### 3.5 风险分级

- 可逆普通操作直接执行；
- 会影响正在进行任务的操作需要二次意图确认；
- 移除成员、终止 Actor、退役频道、设备密钥等高风险操作必须说明影响范围并显式确认。

## 4. 用户旅程 A：注册、登录与恢复

### 4.1 注册和登录

用户填写账户与密码，提交后显示处理中状态；字段错误贴近字段展示，认证失败不清空账户名。成功后进入最近访问的有效频道；没有频道时进入空工作台并引导发现或创建。

### 4.2 会话恢复

页面刷新先恢复会话和频道上下文，再开放输入。会话失效时保存未发送草稿，回到登录页并说明需要重新登录。

## 5. 用户旅程 B：发现并进入频道

用户可在“我的频道”继续工作，也可在“空间”发现频道并查看其可加入状态。统一访问模式为：

- `member_active`：成员且频道可用，可正常收发；
- `member_stale`：成员关系存在但频道暂不可用，只读并等待恢复；
- `member_unavailable`：成员但无法访问，展示原因和恢复路径；
- `observer`：只有观察权限，只读；
- `discoverable`：可发现但未加入，展示介绍和加入入口；
- `retired`：已退役，只读历史或不可进入。

状态合成、优先级和异常处理以[频道访问状态附录](interaction-specs/channel-access-state.md)为准。

进入频道时先展示已有缓存骨架，再同步 feed；同步完成前明确标记。首次进入不应因为 actor 名册尚未返回而错误开放发送。

## 6. 用户旅程 C：发送消息与完成任务

### 6.1 输入

输入区支持普通文本、选择目标 Actor、附件入口和发送。目标默认继承频道中最近合理上下文，但必须始终可见、可修改。发送后生成稳定客户端标识，确保 receipt、feed 和重试能够对账。

### 6.2 过程展示

长任务按一个任务单元折叠展示：用户请求、Agent 临时文本、工具活动、审批和最终结果属于同一任务。默认突出当前阶段，历史细节可展开。

### 6.3 终态

任务最终必须落入完成、失败、取消、被替代或结果未知之一。临时活动不能永远冒充运行中。消息提交、fold 和结构化终态以[普通消息与结构化终态附录](interaction-specs/message-and-structured-terminal.md)为准。

## 7. 用户旅程 D：控制长任务

### 7.1 取消

只有当前用户发起、仍未终结且频道可写的任务显示“取消”。点击后先显示取消请求已提交，再等待账本终态；已完成、无权限或目标不匹配应给出明确原因。取消 receipt 不是任务已经停止的证据。

### 7.2 调整方向（steer）

仅在目标 Actor 声明支持时提供。用户输入新方向后创建可追溯的新请求，并展示后端判定的合并、抢占或排队结果。它不是修改历史消息。

### 7.3 interrupt、stop、terminate、restart

`interrupt` 是打断当前回合，`cancel` 是取消用户任务，两者不混用。Actor 的 stop、terminate、restart 属于高风险治理动作，只放在 Actor 详情或管理区，不放入每条普通消息的主操作栏。

## 8. 用户旅程 E：处理审批

审批卡显示请求方、动作、影响、输入字段、到期状态和允许的决策。用户提交后进入等待账本确认状态。重复处理、已过期、权限变化或并发冲突都保留原审批事实，并显示最终处理者和结果。

审批表单由声明的 schema 生成；不认识的字段采用安全只读降级，不能静默丢失。

## 9. 用户旅程 F：理解并使用 Actor 能力

成员面板按人、Agent、工具分组，隐藏标准系统 Actor。选择 Actor 后通过 describe 能力展示它能接受的动作、参数、风险和当前状态。

简单能力可从消息输入区快捷调用；复杂或高风险能力在详情面板生成结构化表单。提交后的反馈仍遵循全局三阶段模型。

## 10. 用户旅程 G：管理频道

### 10.1 创建频道

有权限的用户从频道列表创建频道，填写名称、用途、父级和可选模板。前端通过正确的治理 Actor 发起创建，并持续跟踪“创建记录 → 频道可观察 → 成员关系可见 → 可打开”。部分阶段失败时展示已完成事实和可恢复动作，不能把部分成功描述为全部失败。

### 10.2 添加参与者

- 添加人：搜索 principal、选择角色、确认邀请或绑定结果；
- 添加 Agent/工具：选择模板或声明、配置必要参数、等待 Actor 就绪；
- 失败时区分权限不足、声明无效、端点不可用和启动失败。

### 10.3 移除、重启与退役

移除参与者、重启 Actor 和退役频道均在管理区完成，先说明对当前任务和历史账本的影响。退役后退出可写模式，但保留允许访问的历史。

## 11. 用户旅程 H：管理模板、声明与端点

空间管理员在独立管理区维护 Actor 模板、频道模板、overlay 和端点。编辑时展示版本、引用关系和变更影响；保存后区分配置已接受与实例已应用。删除被引用对象时必须阻止或给出迁移方案。

这些能力不占据普通频道的主要交互路径。

## 12. 用户旅程 I：管理设备

设备查看、签发、认领、绑定、解绑和退役只对空间管理员开放。设备密钥只展示一次，禁止进入普通日志、Mock 快照和截图基线。后端缺少安全列表投影时，前端不得通过猜测补全设备清单。

## 13. 用户旅程 J：文件与资源

上传采用“创建资源与上传票据 → 数据面 PUT → 账本确认”的流程；下载采用“读取票据 → 数据面 GET”。消息中的文件以资源卡展示名称、大小、类型、状态和下载入口。

票据过期时可重新获取；上传数据完成但账本未确认时显示“已上传，等待登记”，避免重复上传。资源列表放在频道右侧面板。

## 14. 用户旅程 K：定时动作

支持在能力允许时创建延时动作和取消定时器。第一版若后端没有可观察列表，只能展示当前浏览器创建并仍持有标识的定时动作，明确标注“本设备记录”，不得假装是空间完整清单。

## 15. 全局状态、通知与异常

### 15.1 连接状态

连接中、在线、重连中、离线和身份失效具有统一全局提示。离线时允许浏览已缓存内容和编辑草稿，但禁止把未发送内容显示为已提交。

### 15.2 后台操作中心

跨频道的创建、上传、Actor 启动和长任务进入后台操作中心。每项展示所属频道、当前阶段、最终结果和可恢复动作；点击可回到对应上下文。

### 15.3 未读与通知

未读按频道游标计算。当前正在查看且窗口可见时推进已读；审批、失败和任务终态可产生高优先级提示，但不重复轰炸。

## 16. Mock 产品场景

Mock 不是静态接口桩，而是可编排的内存后端。至少提供以下场景包：

1. `first-login`：新用户、无频道、发现与创建引导；
2. `returning-user`：多个成员频道、未读和历史任务；
3. `multi-channel-work`：不同频道独立产生消息，验证切换与后台更新；
4. `long-agent-task`：临时文本、工具活动、steer、cancel 和不同终态；
5. `approval-needed`：待审批、过期、冲突和成功处理；
6. `actor-capability`：describe 与结构化能力调用；
7. `channel-governance`：创建、部分成功、添加/移除 Actor、退役；
8. `space-administration`：模板、声明、overlay 和端点；
9. `file-workflow`：上传、下载、票据过期和账本延迟；
10. `scheduled-action`：创建和取消定时动作；
11. `permission-revoked`：操作过程中权限或成员关系被撤销；
12. `channel-retired`：当前频道运行中退役；
13. `network-chaos`：断线、重连、重复 feed、receipt 延迟和投影延迟。

Mock 必须支持固定随机种子、虚拟时间、独立配置 receipt/feed/OBS 延迟、注入稳定错误码和查询内部状态，使浏览器测试可重复。动态效果由虚拟时间推进，不依赖不可控的真实定时器。

## 17. 响应式与无障碍

- 所有关键动作可用键盘完成，并有可见焦点；
- 状态不只依赖颜色表达；
- 动态账本使用克制的 live region，不逐字朗读流式内容；
- 切换频道后焦点落在频道标题或消息区起点；
- 错误、审批和危险确认具备明确标题与恢复操作；
- 窄屏输入区、取消按钮和审批操作始终可达。

## 18. 分阶段交付

阶段名称和范围以[产品交互总任务 §11](PRODUCT-INTERACTION-MASTER-PLAN.md)为唯一基线：

### 阶段 A：建立产品规格与可靠 Mock

完成 capability manifest、三层 Mock、场景控制、契约漂移检查和真实浏览器 E2E 基础设施，使后续 UI 开发可以稳定依赖 Mock。

状态：已完成，证据见 [PHASE-A.md](PHASE-A.md)。

### 阶段 B：修复当前产品正确性

统一频道访问状态、自我 Actor 映射、结构化终态、完整 provisional 状态，以及退役和权限变化后的 UI 收敛。

状态：已完成，证据见 [PHASE-B.md](PHASE-B.md)。

### 阶段 C：完成核心协作

接入 describe、动态能力表单、cancel、steer/interrupt/queue、高风险 Actor 控制、审批完善和长任务恢复。

状态：已完成，证据见 [PHASE-C.md](PHASE-C.md)。

### 阶段 D：频道治理

完成频道创建、查看和退役，成员与 Actor 管理，异步 serving、频道设置和权限反馈。

状态：已完成，证据见 [PHASE-D.md](PHASE-D.md)。

### 阶段 E：空间治理、资源和自动化

完成模板、声明、overlay、profile、endpoint、安全设备管理、KV 资源、文件数据面、附件和定时动作。

状态：已完成，证据见 [PHASE-E.md](PHASE-E.md)。

## 19. 产品级浏览器验收

一条连续的浏览器测试至少覆盖：注册/登录 → 恢复身份 → 查看我的频道与空间 → 进入频道 → 切换频道并验证账本不同 → 发送消息 → 观察长任务 → 调整或取消 → 处理审批 → 查看结构化终态 → 创建频道 → 添加 Actor → 上传文件 → 经历断线重连 → 退出并恢复会话。

每个阶段还必须有权限不足、投影延迟、并发冲突或网络异常中的至少一种反例。测试断言以用户可见状态和 Mock 内部事实为准，不以固定睡眠时间为准。

## 20. 文档与实施纪律

- 不再为每个后端 verb 编写一份独立长规格；
- 只有同时被三个以上旅程复用、具有复杂状态合成、需要共享 reducer/selector、且分散描述容易导致实现矛盾的主题，才新增技术附录；
- 每阶段连续完成规格校准、Mock、前端实现、浏览器 E2E 和最小真实后端契约验证；
- 阶段内的普通产品细节由本规格直接裁决，不因每个小动作暂停等待确认；
- 只有涉及产品范围扩大、安全边界或不可逆业务决策时，才升级给用户决定。
