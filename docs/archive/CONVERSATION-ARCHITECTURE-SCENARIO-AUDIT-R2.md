# 会话架构：真实交互序列反例审查

日期：2026-09-16。

R1记录保留在第1–5节；R2修订后的逐轨迹复审见第6节。原先的未闭合结论不能抹掉，
但也不应在方案已修订后继续当作尚未处理的同一问题重复汇报。

基线：`CONVERSATION-FRONTEND-REBUILD.md` 第 1.1–1.7 节的行为模型。
性质：**设计层桌面推演，不是运行测试、性能压测或用户场景已通过的报告。**
目标：先用合法操作打破设计，再修订合同；用户不承担逐个发现这些情况的责任。

场景解释以主方案第1.8节J1–J7为准。下面的短轨迹是对完整使用过程的扰动，
不是用故障原句拼起来的需求全集。审查既检查“不能做错什么”，也检查“最终必须完成什么”。

### 推进性审查：没有报错也可能没有完成用户目的

- J1进入：无缓存、连接成功但没有新的push，仍必须主动取得初始内容；不能永远等待事件“碰巧”唤醒加载。
- J2追新：Meta失败/超时不能吞掉需求；在网络最终可用且权限有效的前提下应能完成追赶；永久失败则显式结束并可重试，不能永远假装loading。
- J2重复进入：检查在途请求合并是否丢掉更晚兴趣版本；必须最终完成最后一次校准，不是无限创建并发请求。
- J3历史：持续live不能永远饿死用户当前的历史需求；最高优先级不是其他有界需求永远无进展。
- J5发送：本地事务失败保留稿件；receipt丢失后重试仍保持身份，既不能双发也不能永久无终态。
- J6返回：目标不存在、无权、不可加载均须有明确结果，不无限重试导航。
- J7控制：校准完成必须把stale/unknown推进到有依据的结果，不能靠永久隐藏等待区避免暴露旧状态。

这些结论依赖网络/权限/资源等显式前提；无法对永久离线证明“最终得到后端新消息”，
但能要求离线仍可读已有内容、错误可见、义务可恢复、不静默丢失用户意图。

## 1. 推演方法与独立判据

不以“reducer 输出了 preserve”判定用户位置保持，因为执行器可能根本做不到。
分开检查三个问题：

1. 事实：新数据是否丢失、重复、过期或越过身份边界？
2. 意图：是否出现没有用户授权的导航、跟随、清空或视图切换？
3. 画面：当前阅读内容、焦点、选择、可点击区域是否被破坏？

判据来自用户可观察行为，不来自实现内部函数名。
输入层同时覆盖鼠标滚轮、触摸惯性、滚动条、键盘、文本选择、嵌套容器、辅助技术和路由。
外部扰动覆盖乱序、重复、迟到、丢失、失败、视口变化、异步渲染和页面销毁/恢复。

每条轨迹只要有一个合法排序不能解释，就构成反例；不以其低概率跳过。
任意长度的序列不可能靠列举证明穷尽：闭集事件、状态不变量与版本规则负责推广，轨迹负责找反例。

以下结果用语：

- **规则成立**：文档规则可以导出唯一、符合意图的结果，尚未证明运行实现。
- **合同已修订**：推演发现了文档缺口，本轮修订了设计，仍未实现。
- **能力未闭合**：规则合理但尚无组件/协议能力证明，或约束存在冲突；不能签字通过。

| J4阅读：任务终态已到，缓存旧queued到达，图片同时加载 | 后端状态回退或全窗闪烁，把“没操作”误当“没有变化” | ControlProjection/Presentation/MessageList分别负责；G5控制权威输入仍需落实 |
| J5输入：软键盘出现，流式正文更新，quota事务失败 | 输入丢失、稿件先清后失败、状态提示推高输入框 | Composer/Storage/Surface分离；输入栈可达性仍受G6阻断 |
| J6返回：BFCache恢复、隐藏0高测量、旧导航effect重放、用户马上滚动 | 旧测量破坏布局、重复恢复或抢回用户位置 | 幂等激活/消费及无效测量拒绝；G1已发导航取消仍需组件证据 |
| J7控制：另一设备终结任务或标已读，本地正在复制旧正文 | 远端read frontier控制本地位置，或旧正文缓存恢复当前任务 | 后端任务/跨设备读状态/本地阅读目标分离；选择回收G2及控制G5仍需能力证据 |

额外识别的缺口是**异步派生结果的版本**：只校验请求epoch和用户inputEpoch，仍挡不住
旧Markdown、图表或旧宽度测量在新正文后提交。主方案已补齐其contentRevision/layoutRevision合同。
“用户没有动作”也不是静态场景；必须验证全部外部来源独立触发和交错触发。

## 3. 反例导致的合同修订

### D1 初始内容与空内容不是一回事

首次 activation 产生一个 initial target 决策。数据逐批到达只推进其 resolving；
用户接管后失效，后续批次没有第二次初始化权。
`unknown/partial` 与 `empty-known` 分开，保留已显示内容。只有权威证明为空才显示空会话。

### D2 防止 A→B→A 的旧写入覆盖

session key 相同不等于激活实例相同。activationID 隔离执行权；持久状态的 revision 在同一 session key 内单调递增，
不能每次挂载清零后进行无条件覆盖。跨页/跨 tab 写入需要原子比较或明确的冲突协议；
本次只保证单客户端设计，不宣称已经实现跨 tab/跨设备恢复。

### D3 恢复的是意图，不是“有无 anchor”

保存 mode=following 时，哪怕附有旧 anchor，仍恢复尾随；mode=browsing 才解析阅读书签。
导航目标有效性与数据有无分别处理。不让快照是否存在决定用户模式。

### D4 到尾证据有作用域

`向下操作 + 之后某次 atBottom` 不是充分条件。
到尾观察必须与该主列表用户运动、同一激活期及相容的布局版本关联。
中途数据缩短、容器增高或程序滚动使关联失效时，保留 browsing；随后用户再次操作可建立新证据。
不能因难判断而建立一个永远有效的 `tailArrivalArmed=true`。

### D5 旧投影可丢，事实不可丢

Replica 先拥有事实。Presentation 的旧 baseRevision 失效时，从当前已提交投影及当前 Replica 重算受影响项；
不得把“丢弃旧候选数组”实现成“放弃那批历史”。禁止两个陈旧全量数组互相覆盖。

### D6 阅读可见性不是频道连续性

新消息接收、加载、渲染、用户读到是不同事实。
过滤视图能证明读过的只是其展示集合；如果后端只有一个累积 read cursor，必须明确其代表
“用户主动确认到此为止”还是“连续内容已读”，不能由局部可见消息自动跨越未见内容。
未定义该语义前，过滤视图不自动推进全频道累积 cursor；显式标记已读另有用户授权。

### D7 几何不变量必须满足物理可行域

若锚点在文档中的位置变化为 ΔH，理想新 scrollTop 为旧值 + ΔH。
只有当它落在新文档的合法滚动范围 `[0, max(0, scrollHeight-clientHeight)]` 内，且锚点内容存活，
才有严格保位的可能。否则只能做必要钳制并保留最近语义位置，不自动跟随、不继续补偿振荡。
不能为掩盖这个边界偷偷加无限 spacer；必要钳制与无故跳位必须在诊断中区分。

## 4. 尚未闭合的设计门槛

2026-09-16 已完成代码/接口级审核，裁决见[完整架构审核第4节](/home/xiewanpeng/.atoll/device/daemons/local-device/channels/c0.dev/atoll-web/docs/CONVERSATION-FULL-ARCHITECTURE-REVIEW.md)。

G6 是布局可满足性问题，不能归咎于虚拟列表或网络。

## 5. 从设计审查到自动验证

本轮没有运行任何随机或浏览器压测。以上轨迹应成为集中验证的输入，而不是继续让用户手工发现它们。

- 生成器以 U/B/E 事件族和有效前置条件生成交错序列，显式注入重复、迟到、取消和失效。
- 模型层判定身份隔离、命令权限、无丢失事实、状态单调性和有界需求；失败轨迹缩减并保留种子。
- 组件层以实际可见文字位置、选择/焦点、按钮命中、内容覆盖为 oracle，不以内部 mode/preserve 标志为 oracle。
- 有限设备预算下区分网络缺数据、已有数据未准备、DOM未覆盖和主线程堵塞，分别计量。
- 不能从两两组合通过推导任意组合通过；规则应维持逐步不变量，三方以上关键竞态需专项轨迹。
- 用户验收用于确认真实体验，不充当第一道测试或完整需求枚举。

首次32条推演发现并修订了七类语义合同缺口；随后完整反馈核对新增E01–E10，合计42条设计轨迹。
六项组件/协议/布局门槛仍未关闭。
这否定的是“当前草案已经可直接实施并保证所有场景”的判断，不是否定上述行为模型。
下一阶段必须关闭门槛并形成能力对应关系，不能把失败轨迹变成散落于 UI 的补丁。
